# Phase 4 Plan: Field Audit Workspace & Reference UI Parity

**Goal**: Implement the multi-page field audit workspace with exact visual and structural parity to the reference implementation in `ahfjhabsd/`, including dynamic question loading from the 72-question bank, IndexedDB offline autosave, per-question evidence attachments with magic-byte validation and EXIF stripping, server-side PII detection and rejection, and full multi-page submission/reopening workflows.

---

## Task 1: Database Migration (`V4__audit_workspace_pages_answers_evidence.sql`)
1. Create `audit_pages`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `pilot_location_id UUID NOT NULL REFERENCES pilot_locations(id) ON DELETE CASCADE`
   - `page_number INT NOT NULL`
   - `status VARCHAR(32) NOT NULL DEFAULT 'DRAFT'` (values: `DRAFT`, `SUBMITTED`)
   - `created_by UUID REFERENCES users(id)`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - Unique constraint on `(pilot_location_id, page_number)`
2. Create `audit_answers`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `audit_page_id UUID NOT NULL REFERENCES audit_pages(id) ON DELETE CASCADE`
   - `question_id VARCHAR(64) NOT NULL REFERENCES question_bank(id)`
   - `question_version_id UUID NOT NULL REFERENCES question_versions(id)`
   - `answer_value JSONB NOT NULL DEFAULT '{}'`
   - `is_na BOOLEAN NOT NULL DEFAULT FALSE`
   - `na_reason TEXT`
   - `is_not_assessed BOOLEAN NOT NULL DEFAULT FALSE`
   - `not_assessed_reason TEXT`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - Unique constraint on `(audit_page_id, question_id)`
3. Create `evidence_attachments`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `audit_page_id UUID NOT NULL REFERENCES audit_pages(id) ON DELETE CASCADE`
   - `question_id VARCHAR(64) NOT NULL REFERENCES question_bank(id)`
   - `storage_path VARCHAR(512) NOT NULL`
   - `file_name VARCHAR(256) NOT NULL`
   - `file_size_bytes BIGINT NOT NULL`
   - `mime_type VARCHAR(64) NOT NULL`
   - `sha256_hash VARCHAR(64) NOT NULL`
   - `attestation_confirmed BOOLEAN NOT NULL DEFAULT TRUE`
   - `created_by UUID REFERENCES users(id)`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
4. Create `audit_submissions`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `pilot_location_id UUID NOT NULL REFERENCES pilot_locations(id) ON DELETE CASCADE`
   - `submitted_by UUID REFERENCES users(id)`
   - `submitted_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `page_ids JSONB NOT NULL`
   - `question_version_snapshot JSONB NOT NULL`
   - `reopened_by UUID REFERENCES users(id)`
   - `reopened_at TIMESTAMPTZ`
   - `reopen_reason TEXT`
5. Update `pilot_locations`: ensure valid statuses (`REGISTERED`, `DRAFT`, `READY_FOR_ANALYSIS`, `ANALYSING`, `ANALYSED`, `REOPENED`).

## Task 2: Backend Entities, Services, PII Guards & REST APIs
1. JPA Entities & Repositories in `org.abhisaran.audit`:
   - `AuditPage`, `AuditAnswer`, `EvidenceAttachment`, `AuditSubmission`.
   - Repositories with custom queries for location pages, questions snapshot, and answer maps.
2. PII Detection Guard (`PiiDetector.java`):
   - Regex patterns for:
     - 12-digit Aadhaar numbers (`\b\d{4}[ -]?\d{4}[ -]?\d{4}\b`)
     - 10-digit Indian mobile numbers (`\b(?:(?:\+|0{0,2})91(\s*[\-]\s*)?|[0]?)?[6789]\d{9}\b`)
     - Email addresses (`\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b`)
   - Rejects text with `422 Unprocessable Entity` and explicit descriptive error.
3. Evidence Storage & EXIF Processing (`EvidenceStorageService.java`):
   - Magic bytes check: JPEG (`FF D8 FF`), PNG (`89 50 4E 47`), WebP (`RIFF...WEBP`), PDF (`25 50 44 46`).
   - Image re-encoding via `ImageIO` or metadata clearing to guarantee stripping of EXIF/GPS tags.
   - Storage under random UUID in private uploads folder.
   - Streaming endpoint with authorization check.
4. Services:
   - `AuditPageService`: page append, duplicate (copies answers, omits evidence), delete (DRAFT only), clear (DRAFT only).
   - `AuditAnswerService`: batch answer save, PII guard validation, version snapshot linking.
   - `EvidenceService`: upload with attestation check, file streaming, deletion (DRAFT only).
   - `AuditSubmissionService`: completeness validation (reports any unanswered scored questions), locking pages to `SUBMITTED`, location status update to `READY_FOR_ANALYSIS`, reopening with audit log.
5. Controllers:
   - `AuditController`:
     - `GET /api/v1/locations/:locationId/pages`
     - `POST /api/v1/locations/:locationId/pages`
     - `GET /api/v1/pages/:pageId`
     - `PUT /api/v1/pages/:pageId/answers`
     - `POST /api/v1/pages/:pageId/duplicate`
     - `DELETE /api/v1/pages/:pageId`
     - `POST /api/v1/pages/:pageId/clear`
     - `POST /api/v1/pages/:pageId/evidence`
     - `GET /api/v1/evidence/:id/file`
     - `DELETE /api/v1/evidence/:id`
     - `POST /api/v1/locations/:locationId/submit`
     - `POST /api/v1/locations/:locationId/reopen`
6. Integration Tests (`AuditIntegrationTest.java`):
   - Create pages for location, verify unique page numbering.
   - Save valid answers, verify version snapshot.
   - Submit text containing phone/Aadhaar/email, assert `422 Unprocessable Entity`.
   - Duplicate page, verify answers copied and evidence omitted.
   - Delete page while DRAFT, verify record removed.
   - Submit with unanswered scored question, verify rejection report.
   - Answer all scored questions, submit successfully, verify status `READY_FOR_ANALYSIS`.
   - Reopen location with reason, verify status `REOPENED` and pages return to `DRAFT`.
   - Test evidence upload with magic bytes validation and EXIF stripping.

## Task 3: Frontend IndexedDB Offline Autosave Engine
1. IndexedDB Client (`apps/web/src/features/audit/offlineStorage.ts`):
   - Database `abhisaran_offline_db` with object store `audit_drafts`.
   - Methods: `saveDraft(pageId, answers)`, `getDraft(pageId)`, `clearDraft(pageId)`, `getAllPendingSyncs()`.
2. Sync Coordinator (`apps/web/src/features/audit/useAuditSync.ts`):
   - 500ms debounce on answer changes.
   - Saves immediately to IndexedDB ("Saved on this device", amber status pill).
   - Sends batch `PUT /api/v1/pages/:pageId/answers` ("Synced", green status pill).
   - Catches network failure, flags "Sync error (Tap to retry)" with red status pill and retry queue.

## Task 4: Field Audit Workspace UI (Exact Parity with `ahfjhabsd/`)
1. Create `FieldAuditWorkspace.tsx` in `apps/web/src/features/audit/`:
   - **Sticky Header (56px)**:
     - Brand logo + wordmark `ABHISARAN`.
     - Location subtitle: **Location code only** (e.g., `JH-RCH-SCH-0001`), **never facility name**.
     - Dynamic Save-Status Pill with color indicator (Green = Synced, Amber = Saved on this device, Red = Sync error).
     - PDF Export dropdown ("Download Current Page", "Download All Pages").
     - `⋯` Action Menu popover: Add Page, Duplicate Page, Export Data (JSON), Import Data (JSON), Delete Page, Clear Page.
   - **Page Tabs Strip**:
     - `Page 1`, `Page 2`, `Page 3`, etc. with status badges (`DRAFT` / `SUBMITTED`).
     - `+ Add Page` button.
   - **Section Navigator & Progress Strip**:
     - Sticky progress strip: `"Question n of N · x % complete — y of N answered"` + animated progress bar.
     - Section sidebar on desktop ($\ge 960$px) / jump select on mobile.
     - Real-time search box: filters questions dynamically by keyword or question number (`S04`, `water`).
   - **Question Card Rendering**:
     - Severity badge (`CRITICAL`, `HIGH`, `MEDIUM`, `INFO`).
     - Question canonical text + italicized hint.
     - Rendered input controls for all question types and rubrics:
       - Single-line text, multi-line textarea.
       - Numeric inputs with validation.
       - Percentage input with `%` adornment.
       - Radio pills (`Yes` / `No` / `Partial`).
       - Checkbox chips with multi-selection.
       - Rating 1–5 segmented buttons.
       - `GRID_AFU` matrix checkbox tables (`Available`, `Functional`, `Used`).
       - `CHECKLIST_YNP` tables (`Yes`, `Partial`, `No`, `N/A`).
       - Numeric ratio pairs (working vs sanctioned).
       - "Mark as Not Applicable" toggle with mandatory reason.
       - "Could Not Be Assessed" toggle with mandatory reason.
     - Evidence attachment component:
       - Attestation checkbox modal before upload.
       - File drag-and-drop or picker (jpg, png, webp, pdf, $\le 10$ MB).
       - Thumbnail grid with lightbox view and delete button (while DRAFT).
   - **Bottom Navigation Bar**:
     - `[ Previous ]` · `[ Save ]` · `[ Next ]`
     - "Submit all pages for {CODE}" button.
     - Completeness pre-flight modal listing any missing answers before confirming.
2. Wire into `App.tsx`:
   - Admin view `audit` or launch from "Field Audit Workspace" overview card.
